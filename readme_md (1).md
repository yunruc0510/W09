## 3. 個人回答

### 問題一：測試一中，整理後的桌遊串列有 4 筆資料，為什麼桌遊費用應以 3 人計算？直接把字串拆成 list，和再轉成 set，各自保留了什麼、失去了什麼？

在測試一中，整理後的桌遊串列為 `['amy', 'ben', 'amy', 'cora']` 共 4 筆資料，但其中 `'amy'` 重複出現了兩次。依據活動規則，同一個人在同一場活動中重複報名只算一位參加者，也只收一次該場費用；去重後的實際參加者只有 `amy`、`ben`、`cora` 共 3 人，因此桌遊應收費用應以 3 人計算（$3 \times 120 = 360.00$ 元）。

- **直接把字串拆成 `list`**：
  - **保留了**：原本報名的先後順序、重複報名的紀錄與次數（方便觀察誰重複報名），以及位置索引特性。
  - **失去了**：自動去除重複項目的能力，也無法直接進行交集、聯集、差集等集合比較運算。
- **再轉成 `set`**：
  - **保留了**：不重複的參加者成員（每位參加者只保留一筆），並獲得集合運算（`&`、`|`、`-`）的能力。
  - **失去了**：原本的輸入先後順序、誰重複報名過幾次的紀錄，以及索引位置（因此輸出名單前需要使用 `sorted()` 重新按字母排序）。

### 問題二：測試三中，兩場活動只有 3 位不同的人，為什麼是 6 人次、總應收仍是 600 元？請用集合關係與算式說明。

在測試三中，桌遊集合 $B = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$ 與電影集合 $M = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$ 的成員完全相同：
- **聯集（全部參加者）**：$B \cup M = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$，元素個數 $|B \cup M| = 3$，因此「總不重複人數」為 **3 人**。
- **交集（共同參加者）**：$B \cap M = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$，元素個數 $|B \cap M| = 3$，代表這 3 位參加者同時報名了兩場活動。
- **差集（只參加單場者）**：$B - M = \emptyset$ 且 $M - B = \emptyset$（排序後皆顯示為 `[]`），沒有人只參加其中一場。

「報名人次」計算的是兩場活動各自去重後的參加人數總和，因為這 3 人每人皆參加了 2 場活動，所以：
$$\text{報名人次} = |B| + |M| = 3 + 3 = 6\text{ 人次}$$

收費規則則是兩場活動依各自去重人數分別計費後加總：
- **桌遊體驗應收**：$|B| \times 120 = 3 \times 120 = 360.00\text{ 元}$
- **電影欣賞應收**：$|M| \times 80 = 3 \times 80 = 240.00\text{ 元}$
- **總應收金額**：$360.00 + 240.00 = 600.00\text{ 元}$
